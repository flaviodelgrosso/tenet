# Implementation handoff

Return concise structured information that survives the worker's fresh-context teardown.

## Summary

State what behavior changed and which acceptance criteria it addresses.

## Verification

List only checks actually executed, with outcomes. Keep suggested/unexecuted checks separate.

## Decisions

Record only decisions that constrain later work, such as a public interface, data contract, persistence behavior, compatibility choice, or architectural boundary.

Each useful decision should include:

- decision;
- reason;
- affected area.

## Discoveries

Record repository facts likely to help later workers.

## Risks

Record unresolved, evidence-based risks only.

## Follow-ups

Record useful out-of-scope work. Do not implement it silently.

## Rule

Do not use the handoff to claim completion that repository evidence cannot support.
